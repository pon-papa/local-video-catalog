# Python runtime の配布方式（比較・実測・推奨）

- 作成日: 2026-08-15（**前回の結論を訂正**）
- 目的: 一般利用者が **Python を別途インストールせずに** 使えること
- 制約: One-Folder 完結を崩さない / tkinter GUI が確実に起動する / 巨大 installer は作らない

---

## 0. 前回の結論の訂正

前回「embeddable package を推奨。tkinter 同梱可否のみ未検証」と書いたが、
**これは前提が誤っていた。**

Windows 向け embeddable package には **Tcl/Tk が含まれていない。**
含まれないのは「未検証の細部」ではなく、GUI が起動しないという
**方式の成否そのもの**である。素の embeddable を同梱するだけでは、
Python + tkinter の一般配布版は成立しない。

したがって推奨を取り下げ、Tcl/Tk をどう用意するかを含めて比較し直した。

---

## 1. 実測した事実（このPCで確認）

| 項目 | 実測値 |
|---|---|
| Python | 3.13.14（Microsoft Store 版） |
| Tcl/Tk | 8.6.15 |
| tkinter に必要なバイナリ | `_tkinter.pyd`（0.07 MB）・`tcl86t.dll`（1.76 MB）・`tk86t.dll`（1.52 MB）・`zlib1.dll`（0.14 MB） |
| Tcl/Tk のスクリプト一式（`tcl/`） | 5.32 MB |
| **tkinter を動かすための追加ぶん 合計** | **約 8.8 MB** |

### 検証したこと: Tcl/Tk は移設できる

`tcl/` と関連 DLL を**まったく別のフォルダーへ複製**し、
`TCL_LIBRARY` / `TK_LIBRARY` をそこへ向けて tkinter を起動した。

```
使用中の library: C:\...\Temp\tk_poc_e3jycvmh\tcl\tcl8.6
RESULT: OK
```

**Tcl/Tk は元の場所に縛られない。** 環境変数で指し直せば、
アプリのフォルダー配下に置いた一式で動く。
これが方式 A・B が成立するための前提であり、それは満たされている。

### 検証していないこと（正直に）

- **embeddable package そのものは試していない。** 入手には
  python.org からのダウンロードが要るため、許可なく行っていない
- embeddable の `python313.zip` に tkinter の **Python 側モジュール**
  （`tkinter/*.py`）が含まれるかは未確認。含まれない場合は
  それも同梱が要る（サイズは小さい）
- **このPCの Python は Microsoft Store 版であり、その実体を
  再配布することはできない。** 上の複製はあくまで仕組みの確認であって、
  配布物の作り方ではない

## 2. 比較

| 評価項目 | A. embeddable + Tcl/Tk | B. 通常 runtime の必要部分を同梱 | C. PyInstaller（folder 型） |
|---|---|---|---|
| **tkinter 対応** | ○ Tcl/Tk を足せば動く（移設可を実証） | ○ 同上 | ○ 自動で取り込む |
| **One-Folder 適合** | ◎ すべて APP_ROOT 配下 | ◎ 同上 | ○ folder 型なら可 |
| **配布サイズ（展開後）** | 約 26 MB（embeddable 約17 + Tcl/Tk 8.8） | 約 40〜60 MB | 約 40〜60 MB |
| **Start.cmd からの起動** | ◎ `runtime\python.exe` を呼ぶだけ | ◎ 同上 | ○ exe を呼ぶだけ |
| **src コードの可視性** | ◎ `.py` のまま | ◎ `.py` のまま | ✕ 実質不可視 |
| **更新容易性** | ◎ `src\` を差し替えるだけ | ◎ 同上 | ✕ 再ビルドが要る |
| **透明性** | ◎ 送信しないことを利用者が確認できる | ◎ 同上 | ✕ 確認できない |
| **Python 未導入 PC** | ◎ 動く | ◎ 動く | ◎ 動く |
| **必要な同梱物** | embeddable（PSF）＋ Tcl/Tk（BSD 系）＋各ライセンス | 同左（**入手元に注意**） | 同左が exe へ埋め込まれる |
| **保守コスト** | 中（Tcl/Tk の組み立て手順を維持） | 中〜高（何を含めるかの判断が要る） | 高（ビルド環境の維持） |
| **最大の弱点** | Tcl/Tk を**自前で用意する手順が要る** | **再配布可能な入手元の確保** | 中身が見えない・自己再実行の作り直し |

### 補足

**C（PyInstaller）は追加の作り直しを伴う。**
いま GUI は `sys.executable -m local_video_catalog.pipeline` で
**自分自身を子プロセスとして再実行**している。凍結後はこの呼び出しが
使えないため、子プロセスの起動方式を作り直す必要がある。
「方式決定のために大規模な再設計を行わない」という方針に反する。

**B は A の上位互換ではない。** 「通常 runtime の必要部分」を選ぶには
何が必要かの判断が要り、判断を誤ると利用者の環境でだけ落ちる。
embeddable は**最初からその選別が済んでいる**ぶん確実である。

## 3. 推奨

**A（embeddable package + Tcl/Tk を同梱）を推奨する。**

理由:

1. 追加ぶんは実測 **約 8.8 MB**。展開後 26 MB 程度に収まり、
   「巨大 installer を作らない」方針と両立する
2. **One-Folder を一切崩さない。** runtime も APP_ROOT の中に入るので、
   フォルダーごとコピー・移動しても付いてくる
3. **コードが `.py` のまま残る。** 「外部へ送信しない」ことを
   利用者自身が確認できる。ローカル解析を掲げる以上、C より明確に優れる
4. 現在の「自分自身を `-m` で再実行する」構造を変えずに済む
5. Tcl/Tk が移設可能であることは**実証済み**であり、方式の成否に関する
   未知はもう残っていない

### 残る課題（実装時に解く）

| 課題 | 対応 |
|---|---|
| Tcl/Tk の**再配布可能な入手元** | python.org の Windows インストーラー（PSF ライセンス）から取り出す。Store 版からは取らない |
| embeddable に tkinter の Python 側モジュールが入るか | 入手して確認。無ければ同梱（小さい） |
| ライセンス表記 | PSF（Python）と Tcl/Tk（BSD 系）を `LICENSE` へ追記 |

### 段階的な進め方

**現状（外部 Python を要求）を残したまま A を足す。** これなら
どちらの環境でも動く。

| 段階 | 内容 |
|---|---|
| 1 | `Start.cmd` に「`runtime\python.exe` があれば最優先」の分岐を足す（無ければ現状どおり外部 Python を探す） |
| 2 | python.org の embeddable と Tcl/Tk から `runtime\` を組み立てる手順を `tools\` へ用意する |
| 3 | `tools\make_release.py` に `--with-runtime` を足す |
| 4 | ライセンス表記を追記 |

段階 1 は**いま入れてよい**（runtime が無ければ従来どおり動くだけ）。
段階 2 以降は、embeddable と Tcl/Tk の入手をユーザーが許可した時点で行う。

---

## 4. いまの実運用確認では

**この検討で解析本体の確認を止めない。**
実運用確認用の release は、**このPCにインストール済みの Python を使う**
現状の方式のまま進める。runtime の同梱は v1 の完成条件ではなく、
「利用者が Python を意識しないで済む」ための上積みである。
